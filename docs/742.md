# Later build (7.4.2)

## What is in the binary

- `__JS_EvalInternal` moved to `0x5faf020`. The vardef fetch is still at
  `+0x883` (`0x5faf8a3`) and the walk is the same code, still without a bounds
  check.
- The engine is quickjs-ng 0.18.0 or later. `Date.parse("\u00a02020-01-01")`
  returns a number on this build, which 0.17 does not do.
- Widget JS still runs on QuickJS inside the client. A backtrace from
  `TelegramWidget.request` goes through `QuickJSTrampoline::call`,
  `js_call_c_function`, `js_call_interp` and `JS_CallInternal`.
- A new `twidget::TrustedValidator` creates a fresh `JS_NewContext` and
  evaluates the page through `QuickJSContext::evaluate`.

## Why the 7.4.1 page does nothing here

The page script is compiled as global code, so a top-level indirect `(0,eval)`
has no parent function. The walk that the 7.4.1 page uses is not entered, and
the page runs normally. `poc/742/attempt.html` is that page; it returns `none`.

A function that contains the eval call does reach the walk:

```js
function wrap(){ var a = 1, b = 2;
  (0, eval)('globalThis.f = function ([] = eval("1")) { return a + b; };'); }
```

`poc/742/walk_probe_gen.py` builds a page with that shape. Under a breakpoint at
`base + 0x5faf8a3` it hit once, with `r11=5` and `n_closure_vars=0`. The same
page did not hit again in about eleven later attempts, across fresh pages,
fresh nonces and client restarts. No page content was found that brings the
walk back reliably.

## Negative results

- The plain 7.4.1 pages run on this build and print `none` or `threw`. The
  crash page is the exception: it has been reported to crash 7.4.2 on iOS,
  Android and Linux. One Linux instance here rendered it without dying, which
  is the phase loop missing on that run.
- One SIGSEGV appeared once in the validator thread inside `JS_NewContext`
  (`rax=0x55c4`), called from `twidget::TrustedValidator`. It was not
  reproduced and was not driven by page content.
- Sanitized fuzzing of the fork source with and without the upstream parser fix
  found no memory-safety report in about 3.9 million executions. The harnesses
  covered the JS evaluator and allocation-failure paths, not the host bridge.

## Upstream fix

The branch `fix/parser-scope-oob` in the fork adds two checks: reject a negative
`scope_level` in `add_scope_var` and `pop_scope`, and propagate `push_scope`
allocation failures. Both concern allocation-failure handling, which is not the
path used by these pages. The unchecked index itself is still in the code.
